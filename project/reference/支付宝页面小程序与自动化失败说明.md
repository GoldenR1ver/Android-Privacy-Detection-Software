# 支付宝「页面小程序」架构与动态导航失败说明

本文档说明支付宝 App 在隐私相关页面上的特殊 UI 架构，以及本项目的 Appium 自动化在支付宝上失败的主要原因与已采取的缓解措施。素材来自本项目 `screenGrab` 抓取的 hierarchy、以及 `stage3_lab42_before/支付宝` 的运行日志。

---

## 1. 支付宝不是「纯原生设置页」

支付宝的「设置」「用户保护中心」「隐私设置」等能力，分布在 **两套完全不同的技术栈** 上：

| 层级 | 技术栈 | 典型 resource-id 前缀 | 可见性（无障碍） |
|------|--------|----------------------|------------------|
| 外壳 / 我的 / 部分设置入口 | 原生 Android（AntUI 组件） | `com.alipay.mobile.antui:id/...` | 较好，`text` / `content-desc` 较完整 |
| 用户保护中心及子页面 | **Nebula / XRiver 容器 + H5 小程序** | `com.alipay.multiplatform.phone.xriver_integration:id/...` | 不稳定，列表项常延迟或缺失 |

用户口语中的「页面小程序」，在工程上对应支付宝的 **Nebula（内嵌 H5 容器）** 或 **XRiver 多端运行容器**：一个原生壳里嵌 `com.alipay.mywebview.sdk.WebView`，业务 UI 由前端渲染，而不是传统的 `RecyclerView + TextView` 列表。

---

## 2. 从 hierarchy 能读到的结构

### 2.1 设置页（`screenGrab/output/20260609_050409_setting`）

- 标题栏为原生 AntUI：`title_text` = **「设置」**（`com.alipay.mobile.antui:id/title_text`）。
- 下方为 `RecyclerView`，但本次抓取中 **列表区域几乎没有子项 text/content-desc**（仅见空 `ViewGroup` / 占位 `View`）。
- `element_count` 仅 23，可点击项几乎只有「返回」。

**含义**：你肉眼能看到「用户保护中心」等入口，但 **UiAutomator2 的 `page_source` 在抓取时刻可能尚未暴露这些文案**（H5/动态列表未渲染完、或文案画在 WebView/Canvas 内未映射到无障碍树）。

### 2.2 用户保护中心页（`screenGrab/output/20260609_050429_userDemand`）

典型 Nebula 结构（节选）：

```
nebulax_root_view
  └── h5_web_content
        └── com.alipay.mywebview.sdk.WebView    ← 整页 H5 内容区
  └── penetrableLinearLayout_container        ← 原生标题栏叠在 WebView 上
        └── textView_title = "用户保护中心"    ← 原生标题，可点击
```

特征：

1. **`xriver_integration` 包名**：XRiver 集成层，负责小程序/H5 生命周期。
2. **`h5_web_content` + 自定义 WebView**：页面主体是 H5，不是原生 List。
3. **标题「用户保护中心」在原生 `TextView`**（`textView_title`），页面内菜单（如「隐私设置」「常用隐私设置」）往往在 **WebView 内部**，不一定会出现在与标题同一次 `page_source` 的扁平节点里。

因此：**进入用户保护中心后，顶栏标题能匹配；列表里的「隐私设置」未必能靠 `text="隐私设置"` 找到。**

## 3. 隐私政策路径 vs 真实 UI 路径

政策常见写法（节选）：

```
我的 → 用户保护中心 → 隐私设置 → 常用隐私设置
```

或：

```
用户保护中心 → 隐私设置
```

### 3.1 政策省略了「设置」

真实操作通常是：

```
我的 → 设置 → 用户保护中心 → 隐私设置 / 常用隐私设置
```

「用户保护中心」入口在 **设置页列表** 内，而不是「我的」首页直接可见。  
早期解析得到的路径为：

```
我 > 用户保护中心 > 隐私设置   ❌ 在「我的」页直接找「用户保护中心」
```

这会在第一步就失败，与是否识别小程序无关。

**已缓解**：路径构建时若出现 `我 → 用户保护中心` 且缺少 `设置`，自动插入 `设置`；并配置 bridge `用户保护中心 → 设置`。

### 3.2 「隐私设置」与「常用隐私设置」是两层菜单

政策把两者都写成路径节点，但 UI 上：

- 有的版本显示菜单名 **「隐私设置」**；
- 有的版本直接进入或显示 **「常用隐私设置」**（政策原文也写「隐私设置 → 常用隐私设置」）。

自动化若只匹配「隐私设置」字面，在只显示「常用隐私设置」时会 miss。

**已缓解**：为 token `隐私设置` 增加别名 `常用隐私设置`（先精确名，再别名）。

## 4. 为什么「设置里明明有按钮」仍然 tap miss

综合日志与 hierarchy，失败通常是 **多因素叠加**，而非单一 bug：

### 4.1 抓树时机早于列表渲染

设置页列表可能是：

- 原生壳 + 异步拉取的 H5 配置；或
- 混合列表，首屏仅绘制背景，文案稍后才进入无障碍树。

自动化在点完「我的」后立刻找「用户保护中心」，`page_source` 里还没有该字符串 → 全部选择器 miss。  
**已缓解**：进入设置相关步骤后 `wait_for_label_in_hierarchy` 轮询最多约 6s。

### 4.2 文案在 content-desc 或父节点上

部分支付宝/同类 App 列表项样式为：

- 子节点 `text=""`；
- 父级 `ImageView` / `LinearLayout` 带 `content-desc="用户保护中心"` 且 `clickable=true`。

旧逻辑要求 **可点击节点自身** 的 `text` 精确等于目标 → 漏匹配。

**已缓解**：`label_matches_query_relaxed`、`descriptionContains`、点击可点击祖先容器。

### 4.3 WebView 内节点未导出到 UiAutomator

Nebula 页内 H5 列表依赖 WebView 的无障碍桥接。若未开启或未映射：

- 人眼可见；
- `page_source` 里只有一块 `WebView` + 少量原生 chrome。

此时 **text / scrollIntoView 均无效**，需：

- 更长等待 + 重试 `page_source`；
- 或 DeepSeek 读可见 label 建议 bridge（本项目 LLM 导航）；
- 或后续扩展 WebView context 切换 / 坐标兜底（尚未默认启用）。

### 4.4 回退链消耗步进超时（历史问题）

曾在 15s 步进预算内执行 `miss_try_me_first` 等回退，尚未开侧栏/进设置就超时。  
**已缓解**：步进 40s、回退预算 3s、支付宝路径补「设置」。

## 5. 与本项目组件的对应关系

| 项目机制 | 支付宝场景下的作用 |
|----------|------------------|
| `_expand_implicit_settings_steps` | `我,用户保护中心,*` → `我,设置,用户保护中心,*` |
| `navigation_bridges.json` → `用户保护中心: [设置]` | 直接 tap miss 时先点「设置」 |
| `wait_for_label_in_hierarchy` | 等 H5/列表把文案写入 XML |
| `_TOKEN_TAP_ALIASES` / `label_matches_query_relaxed` | `隐私设置` ↔ `常用隐私设置`、content-desc 子串 |
| `parse_policy_slash_aliases` | 政策里 `A/B` 表示别名，非多步（与小红书 `通知设置/隐私/通用` 同类） |
| LLM bridge（DeepSeek） | 设置页列表无 bridge 时，根据可见 label 猜中间菜单 |

## 6. 成功导航时的预期日志形态

```text
navigate_path_1=我 > 设置 > 用户保护中心 > 隐私设置
tap[我]=ok
tap[设置]=ok
wait_label[用户保护中心]=visible
tap[用户保护中心]=ok
tap[隐私设置]=ok          # 或点到别名 常用隐私设置
```

若卡在 `wait_label[用户保护中心]=timeout`：说明 **设置页列表在无障碍树中仍为空**，属于 WebView/渲染问题，需加长等待、手动确认登录态，或考虑 WebView 专项方案。

## 8. 小结

支付宝隐私相关 UI 的「特殊设计」可以概括为：

1. **路径是混合的**：原生 Tab/设置壳 + Nebula 小程序页 + H5 WebView 内容。
2. **政策路径是压缩的**：常省略「设置」、把「隐私设置/常用隐私设置」写成连续节点。
3. **自动化依赖无障碍树**：小程序页列表不一定及时、完整地出现在 `page_source` 中，导致「界面上有、程序认为没有」。

本项目已通过 **补全路径、bridge、等待渲染、别名与 content-desc 匹配** 覆盖大部分可恢复情况；对 **纯 WebView 内无节点** 的极端情况，仍需额外策略（WebView 上下文、OCR、或人工确认）。
