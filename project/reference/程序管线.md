## 2. 组件职责分工

- `cli.py`
  - 提供统一命令入口：`lab4-1` / `lab4-2` / `lab4-3` / `batch`
  - 负责参数解析与调度工作流
- `config/`
  - `personal_info.yaml`：个人信息知识库（别名、权限、API）
  - `decision_rules.yaml`：判定规则矩阵（后续用于扩展）
- `analyzers/policy/policy_parser.py`
  - 读取知识库并解析隐私政策中的“声明获取项”
- `engine/compare_engine.py`
  - 将“声明项”与“观测证据”做规则比对
  - 输出一致/不一致/待复核等结果
  - 支持从 `rules/decision_rules.yaml` 读取判定矩阵（无需 LLM）
- `reporting/report_exporter.py`
  - 将结果导出为结构化 JSON 报告
- `workflows/lab4_1_pipeline.py`
  - 串联最小闭环：`policy_parser -> compare_engine -> json report`
- `ingestion/legacy_bridge.py`
  - 将 `review_bundle.json` 的旧人工标签映射到新 schema，形成可复用 claim 数据

## 3. Lab4-1 最小闭环数据流

输入：
- `policy_file`：隐私政策文本（`.txt`）
- `taxonomy_file`：个人信息知识库（默认 `config/personal_info.yaml`）
- `evidence_file`（可选）：证据文件（JSON，含 `observed_pii`）

处理步骤：
1. 读取政策文本
2. 从 `personal_info.yaml` 加载分类词表
3. 通过别名匹配提取政策声明信息类型（`declared_pii`）
4. 读取观测证据（`observed_pii`，无则为空）
5. 规则比对并生成判定结果：
   - `consistent`：声明且观测到
   - `inconsistent_high_risk`：未声明但观测到
   - `declared_not_observed`：声明了但未观测到
6. 导出 `*_lab4_1_report.json`

输出：
- 单 APP 报告：`output/lab4_1/<app>_lab4_1_report.json`
- 报告包含 `claims`、`evidence`、`verdicts`、`summary`

## 4. 命令使用方式

在项目根目录执行：

```bash
python -m src.privacy_audit.cli lab4-1 --app-name Keep --policy-file input/policies/Keep.txt --evidence-file input/evidence/Keep.json
```

或在 `src` 目录执行：

```bash
python -m privacy_audit.cli lab4-1 --app-name Keep --policy-file input/policies/Keep.txt --evidence-file input/evidence/Keep.json
```

批量执行（当前 `batch` 默认打通 `lab4-1`）：

```bash
python -m privacy_audit.cli batch --apps Keep,支付宝 --policy-dir input/policies --evidence-dir input/evidence
```

阶段0到阶段1桥接：

```bash
python -m privacy_audit.cli bridge-stage1 --review-bundle-file ../oldsrc/analyzer/data/main/review_bundle.json
```
